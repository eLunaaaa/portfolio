## 새 주문 상태

`OFFERED`에서 사용자가 거절하면 `REJECTED`, 시간이 지나면 `EXPIRED`입니다. 매수를 승인하면 새 계좌·호가로 다시 검사합니다. 조건이 바뀌면 `FAILED`입니다.

주문 API 호출 **이전**에 제안의 `SUBMITTING` 상태와 매수 원장을 **같은 트랜잭션으로** DB에 커밋합니다. 전송 성공은 `ACCEPTED`, 명시적 실패는 `FAILED`, 응답을 알 수 없는 경우는 `UNKNOWN`으로 기록합니다. 프로그램이 `SUBMITTING` 중 종료되면 재시작 때 `UNKNOWN`으로 복구합니다.

`ACCEPTED`/`UNKNOWN`의 종목은 결과 확인 전 추가 매수하지 않습니다. 명시적인 체결·취소 상태와 잔고 반영을 확인한 뒤 원장을 정리합니다. 서버에서 아직 미체결/잔고로 보이지 않는 전송액도 로컬 예약금으로 계산하므로, 잔고 반영 지연 중 다른 종목에 같은 돈을 중복 배정하지 않습니다. 계좌의 주문가능금액을 임의로 음수로 변경하지 않습니다.

| 재현한 문제 | 수정한 구조 | 확인한 결과 |
