# 개선한 자동화 판단 기준

## 전체 순서

뉴스 수집 → 기업별 문맥 분리 → 확정성·사건 방향 분석 → 동일 사건 통합 → 계약 규모·시장 조건 확인 → LCD/부저 → 매수 버튼 → 계좌/호가 재검사 → 지정가 주문 → 체결·취소 확인 → 보유종목 관리 순서입니다.

매수는 버튼 승인이 필요합니다. `auto_exit: true`이면 이 프로그램에서 매수한 종목은 아래 청산 조건에 따라 자동 매도합니다. 기본 실행 모드는 `paper`입니다.

## 뉴스의 의미와 중요도

- **확정 호재**: 수주·공급계약, 실적 개선·흑자전환, 투자 확대, 주주환원 등을 사건군별로 합산합니다.
- **악재**: 적자·손실·계약 해지·리콜·소송 등을 먼저 판별합니다. ‘사상 최대 적자’도 호재가 되지 않습니다.
- **검토 뉴스**: 전망·예상·가능성·추진·검토·부인·사실무근·불발 등의 표현은 확정 매수로 처리하지 않습니다.
- **기업 구분**: ‘A사 적자, B사 수주’처럼 절이 나뉜 제목은 기업별로 사건을 계산합니다. 한 절에 여러 기업이 섞여 관계가 모호하면 검토 대상으로 남깁니다.
- **금액 확인**: 계약만으로 매수하는 경우 제목의 금액과 설정의 `annual_revenue_won`으로 매출 대비 비중을 계산합니다. 기본 `require_contract_materiality: true`에서는 기준을 충족해야 합니다. 연매출 0은 미입력 값이며 임의의 매출을 만들지 않습니다. 별도의 확정 실적 개선 근거가 함께 있으면 그 근거도 적용합니다.

방향 점수와 중요도는 다른 값입니다. 매수는 방향 점수 3 이상과 확정성 검사를 통과해야 합니다. 부저는 매수 여부와 무관하게 중요도 5 이상에서 울립니다. 사건군별 초기 점수는 README에 정리했습니다.

## 동일 사건과 시간

DB의 사건 원장은 종목·사건군·금액·핵심 단어를 비교합니다. 최초 보도에서 48시간 이내인 유사 보도는 같은 사건으로 묶고, 최초 보도 시각을 유지합니다. 금액이 달라지거나 정정·취소 등 방향이 달라진 사건은 별도 항목으로 남깁니다.

같은 사건에 대해 이미 승인·거절·만료된 제안은 재제안하지 않습니다. 장 시작 전이거나 일시적으로 거래량 조건이 부족해 제안을 만들지 못한 뉴스는 다음 수집 주기에 조건을 다시 확인합니다. 이때 같은 뉴스 알람을 반복하지 않습니다.

뉴스 후 가격 변화는 **프로그램이 해당 사건에서 처음 관측한 호가**와 비교합니다. 기사 게시 시각의 과거 가격을 현재 가격으로 추정하지 않습니다.

## 시장 조건

| 설정 | 초기 값 | 검사 내용 |
|---|---:|---|
| `max_spread_pct` | 0.5 | `(매도호가−매수호가)/매도호가 × 100` 상한 |
| `max_day_rise_pct` | 5.0 | 전일 종가 대비 현재가 상승률 상한 |
| `max_news_rise_pct` | 2.0 | 해당 사건 최초 관측 호가 대비 상승률 상한 |
| `min_volume_ratio` | 1.0 | 시간 보정 상대 거래량 하한 |
| `min_contract_revenue_pct` | 1.0 | 계약 단독 근거의 연매출 대비 금액 비중 하한 |

상대 거래량은 `현재 누적 거래량 / (과거 20개 일봉 평균 거래량 × 장 경과 비율)`입니다. 경과 비율은 390분 기준으로 계산하며 0.05~1.0 범위로 제한합니다. 가격과 거래량 자료가 부족하면 매수 조건을 통과시키지 않습니다.

키움 모드에서는 PC 수신 시각 외에 호가 응답의 거래소 시각도 확인합니다. 시장 조건은 제안 때와 승인 직후 모두 검사합니다. 수량은 수수료 포함 예산으로 계산하고, 화면의 지정가를 초과하는 가격으로 매수하지 않습니다.

## 전략 선택

| `strategy_mode` | 매수 신호 |
|---|---|
| `news` | 확정 뉴스 점수 + 계약 규모 + 시장 조건 |
| `rsi` | 뉴스와 독립적인 MA20 > MA60, RSI(2) < 5, 이틀 변화 < −2% + 시장 조건 |
| `combined` | 뉴스 조건과 RSI 조건을 모두 충족 + 시장 조건 |

```sh
python -m stockauto --port COM3 --strategy news
python -m stockauto --port COM3 --strategy rsi
python -m stockauto --port COM3 --strategy combined
```

## 청산·손실·미체결 관리

아래 값은 변경 가능한 초기 설정입니다. 설정 파일에서 본인 계좌 수수료·세금·전략 기준을 지정합니다.

| 설정 | 초기 값 | 동작 |
|---|---:|---|
| `stop_loss_pct` | 3.0 | 평균 매입가 대비 최우선 매수호가가 3% 이상 하락하면 청산 요청 |
| `take_profit_pct` | 6.0 | 같은 기준으로 6% 이상 상승하면 청산 요청 |
| `max_holding_days` | 5 | 보유 기준 시각에서 5일 경과하면 청산 요청 |
| `daily_loss_limit_pct` | 2.0 | 당일 최초 평가자산 대비 2% 하락하면 당일 신규 매수 중단·관리 포지션 청산 요청 |
| `rsi_exit` | true | 수익 구간에서 RSI(2) > 80이면 청산 요청 |
| `cancel_after_seconds` | 120 | 확인된 본 프로그램의 매수 미체결이 120초 지나면 잔량 취소 요청 |
| `risk_poll_seconds` | 30 | 계좌·미체결·청산 조건 재검사 간격 |

손절→익절→기간→RSI 순서로 검사하고, 일일 손실 한도 도달은 최우선으로 적용합니다. 일일 기준과 중단 상태는 DB에 저장해 재시작으로 초기화되지 않습니다. 평가자산이 누락되면 신규 매수는 중단하지만 이를 손실 발생으로 해석해 일괄 청산하지 않습니다.

보유 시작은 브로커가 매입 시각을 제공하면 그 시각을 사용하며, 시각이 없는 잔고는 DB에 저장한 최초 추적 시각을 사용합니다. 일일 기준은 거래소의 시초 자산이 아니라 **당일 이 프로그램이 처음 읽은 정상 평가자산**입니다.

기본 `manage_existing_positions: false`이므로 다른 수동 보유종목은 자동 청산 대상으로 삼지 않습니다. 청산은 최신 호가·매도 가능 수량·미체결을 다시 확인한 후 최우선 매수호가의 **지정가 매도**로 요청합니다. 주문 전송과 실제 체결은 구분합니다. 매수 허용 시간은 09:00~15:00, 프로그램의 청산 허용 시간은 09:00~15:20이며 주말과 설정한 휴장일은 제외합니다.

원격 주문번호가 확인되지 않은 주문은 종목명만으로 취소하지 않습니다. 부분 체결 후 잔량 취소 시 확인된 체결 수량을 소유 원장에 보존하고, 일부 매도 뒤 남은 프로그램 소유 수량도 계속 관리합니다. 수동 추가 매수 수량은 기본 자동 청산에 합치지 않습니다. 응답 미확정은 재전송하지 않고 명시적인 증권사 상태로만 정리합니다.

## 같은 조건의 전략 비교

```sh
python -m stockauto.replay examples/replay_sample.json --output examples/replay_result.json
```

입력은 `bars`와 `news`가 있는 JSON입니다. `bars`에는 timezone 포함 `at`, `code`, 정수 원 단위 `open`, `close`, `volume_ratio`를 넣습니다. 호가가 있으면 `ask`, `bid`도 지정할 수 있습니다. `news`에는 `published_at`, `title`, `link`를 넣습니다. 봉은 시간순으로 정렬하고 같은 시각/코드의 중복을 거부합니다.

각 전략은 동일한 초기 자금·수수료·매도 세금·슬리피지·청산 규칙을 사용하며 `risk_enabled`·`auto_exit`의 활성 여부도 반영합니다. 해당 시각까지 게시된 뉴스와 종가만으로 판단하고, 주문은 **다음 봉 시가**에 비용을 적용하여 계산합니다. 매수 지정가를 넘으면 체결하지 않고, 매도 지정가보다 낮으면 매도 주문을 대기 상태로 유지합니다. 버튼 승인은 신호 발생 시 수락한다고 가정합니다.

출력에는 총자산 수익률, 최대 낙폭, 완료 거래 수, 승률, 종료 시 보유 수, 신호·체결 시각과 거래별 손익이 포함됩니다. 완료 거래가 없을 때 승률은 0이 아니라 `null`입니다. 예제 입력·결과는 `synthetic: true`인 가상 데이터이며, 실제 거래 성과 기록과 구분합니다.

## 뉴스 상태 변경과 승인 무효화

현재 제안의 보도 시각 이상인 새 악재·미확정 보도는 해당 종목의 기존 승인 근거를 차단합니다. 이전 악재가 뒤늦게 수집돼도 최신 차단 시각을 되돌리지 않습니다. 승인 전에는 제안을 취소하고, 승인 후 접수된 주문은 원격 번호가 확인된 매수 미체결 잔량을 취소 대상으로 넘깁니다. 이미 체결된 수량의 매도는 별도의 청산 규칙을 따릅니다.

이 검사는 뉴스·결합 전략에 적용합니다. 뉴스와 독립적인 RSI 모드는 기존 RSI·시장 조건을 사용합니다. 실행·재생은 같은 `strategy.py`를 호출하며, 재생 결과의 `signals`와 `fills`에 승인 수량·지정가·실제 계산 수량을 함께 기록합니다.
