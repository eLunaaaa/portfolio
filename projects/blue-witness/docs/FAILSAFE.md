## 개인 역할과 목표

**이민석은 시스템 전체의 Fail-safe 구조를 설계했습니다.** 카메라·AI·시간 동기화·IPC·업로더·서버를 연결하는 과정에서 ‘어떤 장애를 누가 감지하고, 무엇을 보존하며, 어느 단계부터 다시 시작할지’를 정리했습니다. 모듈별 세부 구현·후속 강화와 통합 시험은 팀과 함께 수행했습니다.

목표는 단순히 죽은 프로세스를 다시 띄우는 것이 아니라, **이미 확보한 사고 영상을 보존하고 복구 후 수집·전송을 이어갈 수 있게 하는 것**입니다. 모든 장애에서 데이터 손실이 절대 없다고 보장하는 설계는 아닙니다.

## 계층별 대응

| 장애 계층 | 감지·판단 | 복구·보존 전략 |
|---|---|---|
| 프로세스 종료·중요 스레드 정지 | 각 업무 스레드의 monotonic 진행 기한 | 정상 업무 진행 시에만 watchdog 알림, 정지 시 알림 중단 → systemd 재시작 |
| 카메라 frame 무수신 | 일정 시간 새 정상 frame 없음 | 카메라 재초기화, 복구 실패 시 프로세스 실패 종료·재시작 |
| IPC 상대 미기동·응답 중단 | connect·I/O timeout, 메시지 type·sequence·길이·버전 검사 | 유한 대기·연결 정리·재시도. 실패한 영상 인계는 디스크 기록으로 유지 |
| 영상 생성·인계 중 종료 | `.part`·`.handoff`와 파일 공개 단계 | 파일·디렉터리 fsync와 rename, 재시작 후 완성 파일·인계 기록 대조 |
| 네트워크·TLS·서버 일시 장애 | 연결·전송·저장 확인 실패 | spool·큐 보존, `PEND` 상태와 backoff, 연결 복구 후 재전송 |
| 서버 저장 후 ACK 유실 | 로컬 완료 여부 불확실 | 사고·차량·SHA·저장 상태를 조회해 확인, 필요 시 멱등 재전송 |
| 업로더 전송 도중 재시작 | DB의 `UPLOAD` 잔존·spool 대조 | `PEND` 복구와 startup reconciliation으로 전송 재개 |
| 서버 병합 중 종료·늦은 영상 | 미완료 merge job·새 증거 revision | 작업 복구·재시도·새 revision 병합, 원본과 기존 결과 보존 |
| 배포 실패 | 사전 권한·서비스·IPC·P2P smoke check | 배포 중단과 실패 장치 이전 파일·설정·서비스 상태 복원 |

각 항목은 정리 기준 버전의 구현을 요약한 것이며, 모든 행의 코드를 본인이 단독 작성했다는 뜻은 아닙니다. 배포 복원 등의 후속 강화에는 팀원의 개선이 포함됩니다.

## 정상 대기와 고장을 구분

```text
업무 스레드가 유한 대기·재시도 중 → 자신의 진행 기한 갱신 → 서비스 유지
업무 스레드 진행 정지           → 기한 만료 → watchdog 알림 중단
                                              ↓
                                      systemd 프로세스 재시작
                                              ↓
                            디스크 기록·큐 대조 → 미완료 작업 재개
```

감시 스레드가 단순히 살아 있다는 이유만으로 알림을 보내면 정지한 Worker를 숨길 수 있습니다. 공통 watchdog은 중요한 Worker별 기한을 확인하며, 하나가 정지하면 실패를 고정해 다른 Worker의 진행으로 덮이지 않도록 합니다.

서버가 꺼져 있거나 Queue가 비어 있는 상태는 정상적인 대기일 수 있습니다. 네트워크 실패와 thread hang을 분리해 불필요한 재시작을 줄이고, 촬영·로컬 영상 보존을 계속할 수 있도록 합니다.

## 완료 상태의 경계

| 완료 신호 | 의미 | 의미하지 않는 것 |
|---|---|---|
| 카메라 인계 ACK | Uploader가 영상 보존·Queue 등록을 수락 | 서버 저장 완료 |
| 서버 저장 ACK | 서버가 해당 사고·차량의 파일을 저장하고 계약에 맞게 응답 | 병합 완료·사용자 열람 완료 |
| 병합 완료 | 특정 revision의 병합 파일 생성 | 아직 도착하지 않은 모든 차량 영상 수신 |

디스크 기록은 재시작 복구에 쓰고, 멱등성은 응답 유실 후의 중복 업로드를 다룹니다. 복구 중에도 사고 ID·촬영 구간·해시를 유지해야 다른 사고나 다른 파일로 잘못 완료 처리하지 않습니다.
