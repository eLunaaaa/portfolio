# 기술 선택과 트러블슈팅

[프로젝트 개요](../README.md)

## 1. 프레임 단위 분리보다 촬영 묶음 분리

연속 프레임을 무작위로 나누면 비슷한 화면이 train과 test에 동시에 들어가 평가가 과도하게 높아질 수 있습니다. 원본 영상·세션·해시를 기록하고 같은 원본 계열을 하나의 split에 배정했습니다. 자동 박스는 작업량을 줄이는 초안이며 사람이 승인한 라벨과 구분합니다.

## 2. 모델 성능과 실행 계약을 함께 관리

학습 코드에서 좋은 결과를 얻어도 장치의 BGR/RGB, 0~255/정규화, letterbox 위치, grid decode가 다르면 검출이 어긋납니다. ONNX 입출력 이름·shape·dtype와 C++ 후처리를 맞추고, 내보내기 도구가 공통 실행 설정을 읽도록 구성했습니다. Nano는 비교 실험, Tiny는 최종 배포 모델로 구분합니다.

## 3. 촬영 callback에서 긴 작업 제거

추론과 MP4 인코딩이 다음 프레임 수신을 막으면 사고 전후 구간이 끊깁니다. 촬영·대기열·Snapshot·추론/저장·인계를 나누고 버퍼 참조 수명과 해제를 관리합니다. ‘zero-copy’라는 표현은 Snapshot이 프레임 전체를 복사하지 않는 범위이며, 색 변환·모델 입력·인코딩의 모든 복사를 없앴다는 뜻은 아닙니다.

## 4. 시간과 ID의 의미 분리

Unix epoch ns는 촬영 구간 비교에, monotonic clock은 타임아웃에 사용합니다. `event_id`는 차량들이 공유하는 사고를 식별하고, 원본의 촬영 시각은 프레임 정렬을 결정합니다. 시간 단위 오해로 1970년이 표시된 사례와 action/event 명칭 변경을 겪으며 전송 규약·변환 검증·표시 형식의 경계를 정리했습니다.

## 5. 영상 저장 성공과 웹에 보이는 상태

파일을 받았다는 ACK와 병합 완료는 다릅니다. 첫 영상 이후 수집 마감, Worker 선점, 지연 업로드에 대한 재병합을 분리합니다. 사고차 미수신의 검정 타일은 영상 손상이 아니라 대체 화면일 수 있으며, 저장 수·실제 병합 수·대체 칸 수를 혼동하지 않아야 합니다. 모드 전환·인증 창의 비동기 응답은 최신 선택에만 적용해야 합니다.

## 6. 헬스 응답은 차량 인증 성공이 아님

공개 health는 서버 가용성을 확인하는 200 응답을 줄 수 있지만 업로드는 노드 키 검증이 필요합니다. NAT 뒤의 여러 Pi는 같은 IP로 보일 수 있으므로 IP·헬스 횟수만으로 차량을 확정하지 않습니다. 관리자 로그는 인증된 node ID와 미인증 주장 ID를 구분하고 API 키·쿠키·원본 요청 body를 기록하지 않습니다.

## 7. CI 재현성과 배포 권한

Mac에 있는 FFmpeg가 Windows runner에도 있다고 가정하면 테스트 준비 단계부터 실패합니다. OS별 의존성·미디어 기능을 준비하고 검사해야 합니다. 장치 배포 역시 SSH 연결 성공만으로 충분하지 않아, 교체 전 `sudo -n` 권한 확인과 실제 서비스·IPC·P2P 연결 점검을 추가했습니다. 최신 캐시·SHA 검증·타임아웃·복원 강화는 팀의 후속 개선을 포함합니다.
