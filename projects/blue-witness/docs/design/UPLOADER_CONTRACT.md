# Uploader 연동 — 재시작과 ACK 유실을 견디는 완료 경계

[서버 수신 코드](../../source/server/backend/app/api/evidence.py) · [서버 저장 코드](../../source/server/backend/app/services/storage.py) · [팀 Uploader](../../source/uploader)

## 담당 경계와 문제

본인은 전체 Fail-safe 구조와 서버 측 저장·ACK 계약을 설계하고 Uploader 전체를 개발했습니다. 이후 CD 연동 과정의 팀 수정도 포함한 전체 모듈을 source/uploader에서 확인할 수 있습니다. 핵심 질문은 ‘보냈는가’가 아니라 **어디까지 안전하게 완료됐는가**입니다.

네트워크 전송 도중 연결이 끊기면 서버에 저장됐는지 모를 수 있습니다. 다시 보내면 중복 처리 위험이 있고, 성공으로 처리하면 실제 미저장 파일이 사라질 수 있습니다. 메모리에만 작업을 보관하면 프로세스 재시작 때 사라집니다.

## 선택 1. 영속 spool과 상태 DB

영상·metadata를 fsync하고 directory rename으로 공개한 뒤 Queue에 등록합니다. 원자 공개와 지속성은 다른 개념이므로 둘을 함께 다룹니다. 인계 ACK는 이러한 로컬 보존·등록 완료 이후의 신호입니다.

| 상태 | 뜻 | 보존 원칙 |
|---|---|---|
| PEND | 전송 순서·backoff·확인 대기 | 원본·metadata 유지 |
| UPLOAD | Worker가 작업을 선점해 전송·확인 | 미완료로 남을 수 있음 |
| DONE | 서버 저장 계약 확인 | 정책에 따라 후속 정리 가능 |
| FAIL | 인증 등 운영자 조치가 필요한 실패 | 성공으로 오인해 삭제하지 않음 |

## 선택 2. 재전송 전에 완료 여부 확인

ACK에는 요청한 사고·차량·저장 상태·해시 등 계약의 일치를 확인합니다. HTTP 2xx만으로 DONE을 만들지 않습니다. 응답이 유실되거나 불완전하면 확인 필요 상태를 보존해 서버 저장 조회를 수행합니다.

```text
로컬 등록 완료 → 전송 → 유효한 저장 ACK → DONE
                    └─ ACK 불명 → PEND·확인 필요
                                      ├─ 서버 파일·해시 일치 → DONE
                                      └─ 저장 없음 → 보존 원본 재전송
```

다시 보내도 같은 사고·차량·파일은 멱등 처리할 수 있어야 합니다. 식별자가 같다는 이유만으로 다른 파일까지 성공으로 처리하지 않습니다. 저장 상태 조회 404는 곧바로 인증 실패가 아니라 해당 파일의 저장 기록이 없다는 의미입니다.

## 선택 3. 단절과 hang 구분

정상 네트워크 재시도는 살아 있는 업무입니다. 유한 timeout·backoff 중 Worker가 진행 기한을 갱신한다면 watchdog이 죽여서는 안 됩니다. 실제 업무 정지일 때만 재시작하고, 그 후에도 spool·DB가 남아 있어야 합니다.

최신 팀 구현은 연결·서버 일시 오류에 5초부터 최대 60초 backoff를 적용합니다. 인증 401/403 같은 영구 성격의 오류는 정상 전송 대기와 구분합니다. 오류별 세부 처리는 고정 원본 버전의 Uploader 규약이 기준입니다.

## 시작 시 복구

전송 중 남은 UPLOAD를 PEND로 돌리고 spool·DB를 대조합니다. 단순히 상태값만 바꾸는 것이 아니라 파일·metadata가 실제로 존재하는지 확인해야 합니다. ID·촬영 구간·SHA는 최초 자료를 유지하고 네트워크 재시도 때 새 사고로 생성하지 않습니다.

## 보안과 실패 경계

TLS 오류가 나면 인증서를 무시하거나 HTTP로 자동 downgrade하지 않습니다. key는 로그·포트폴리오에 기록하지 않습니다. 로컬 보존·TLS·파일 hash는 서로 다른 문제를 해결하며 어느 하나로 다른 검사를 대체하지 않습니다.

## 검증

- 서버 ACK·hash·멱등 조회는 복제된 서버 테스트로 확인합니다.
- 단절 복구 3회·영상 12건은 팀 통합 자료의 사건·차량·파일 hash로 연결합니다.
- 로컬 ACK 후 서버 미저장, 서버 저장 후 ACK 유실, 전송 중 종료를 별개 시험으로 봐야 합니다.
- [큐 중복·재시작·ACK·HTTP 검사](../../../../scripts/check_uploader.py)에서 실제 C 구현의 회귀 동작을 확인합니다.
