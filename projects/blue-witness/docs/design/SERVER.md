# 서버·웹 — 받은 파일을 사고 단위의 재생 가능한 증거로 바꾸기

[소스](../../source/server/backend/app) · [테스트](../../source/server/backend/tests) · [설계 선택](DECISIONS.md)

## 문제와 제약

여러 차량의 영상은 동시에 오지 않습니다. 파일 도착·실제 촬영 구간·서버 저장·병합·열람은 서로 다른 사건입니다. 시연 규모에서는 설치를 단순하게 유지하면서도 중복 업로드·서버 재시작·늦은 영상·접근 권한을 다뤄야 했습니다.

## 선택 1. SQLite + 원본 파일 + 작업 상태 분리

대형 외부 DB·분산 큐를 바로 추가하기보다 SQLite로 사건·증거·병합 작업을 관리하고 영상은 파일로 보존합니다. 의존성과 현장 설치 부담을 낮추는 선택입니다. 수평 확장·다중 호스트 동시 작업은 별도 설계가 필요하며 현 구조의 성과로 주장하지 않습니다.

| 데이터 | 의미 | 코드 |
|---|---|---|
| events | 공통 사고 ID·사고 시각·차량·상태 | `db/schema.sql` |
| evidence | 차량별 실제 영상 경로·촬영 구간·해시·저장 상태 | `db/evidence_repository.py` |
| merge_jobs | 선점·재시도·revision을 관리하는 병합 작업 | `db/merge_job_repository.py` |
| 접근 데이터 | 사용자 세션·소유 관계·영상 접근 | `services/portal_access_service.py` 등 |

## 선택 2. HTTP 응답과 실제 저장 보장 연결

`services/storage.py`에서 경로·SHA-256·실제 파일과 저장 상태를 다룹니다. 원본의 디렉터리도 sync하는 이유는 파일 내용 기록만으로 최종 경로의 지속성을 완전히 설명할 수 없기 때문입니다. 동기화는 비용이 있지만 사고 증거 보존이라는 목적에서 필요합니다.

멱등 재전송은 ‘같은 event ID이니 무조건 성공’이 아닙니다. 사고·차량·파일 상태·해시를 대조해야 다른 내용을 잘못 완료 처리하지 않습니다. 저장 ACK·재조회 계약을 업로더와 맞춥니다. `test_upload_ack_contract.py`, `test_evidence_storage_status.py`가 이 경계의 근거입니다.

## 선택 3. 무한 대기 대신 12초 수집 창 + 늦은 영상 revision

모든 차량이 올 때까지 기다리면 관측되지 않은 차량 때문에 영상을 영원히 못 볼 수 있습니다. 첫 정상 저장 이후 기본 12초를 기다리고 최소 1개로 병합합니다. 다음 업로드마다 마감을 미루지 않아 끝없는 연장을 막습니다.

늦게 도착한 영상은 현재 결과를 없애지 않고 다음 revision으로 반영합니다. 병합 중 도착하면 작업 뒤에 재실행할 필요가 있습니다. 이 선택은 빠른 확인과 최종 완성도를 동시에 추구하지만 재인코딩·디스크 비용이 증가합니다.

`collection_service.register_evidence_for_collection()`·`refresh_collection_states()`, `merge_worker.run_merge_worker_cycle()`·`execute_claimed_merge_job()`가 경계입니다. 중단된 RUNNING 작업 복구와 한 작업의 선점은 repository 트랜잭션에서 다룹니다. 실패는 제한된 backoff로 재시도하고 무한 CPU 재실행을 피합니다.

## 선택 4. 화면 칸보다 촬영 시각 우선

영상은 시작·종료 timestamp로 trim/pad합니다. 공통 구간만 보는 `common`과 합집합을 보는 `extended`를 구분합니다. 업로드 순서나 전체 길이만 맞추는 방식보다 시간 의미를 보존하지만, 시간 오차와 검정 padding을 명시적으로 다뤄야 합니다.

사고차를 첫 위치에 두고 미수신이면 대체 칸을 둡니다. 실제 비율과 영상 수별 레이아웃으로 화면 활용을 높입니다. 수신 수는 DB 원본, 실제 병합 수는 선택 revision의 계획에 들어간 비대체 영상으로 구분해야 합니다. CAR_03 제외는 시연 정책이며 모든 서비스에서 영구 제외해야 하는 도메인 규칙은 아닙니다.

## 선택 5. 재인코딩 대신 브라우저 재생 조절

7초부터 0.25배속 보는 기능은 브라우저에서 처리해 원본 파일을 변경하지 않습니다. 전체·목격·사고 차량 영상은 같은 시간축의 서버 결과를 선택합니다. 모드를 바꿀 때 위치·배속을 유지하고, 로딩 중 누른 최신 재생 명령이 오래된 응답에 덮이지 않도록 다룹니다.

## 인증과 UI 상태

노드 업로드 키, 사용자 로그인, 사고 영상 접근, 관리자 권한은 분리합니다. 공개 health 200을 노드 인증 성공으로 간주하지 않습니다. 관리자 로그는 메모리 bounded buffer이며 secret·쿠키·body를 보관하지 않습니다. NAT IP만으로 발신 차량을 확정할 수 없습니다.

웹에서는 최신 차량 선택·모달 세션·영상 요청의 생명주기를 나눕니다. 자동 갱신이 선택을 되돌리거나 늦은 응답이 다른 사고를 덮지 않도록 회귀 테스트를 둡니다. 내부 event ID·정밀 시각은 상세로 숨기고 기본 화면은 읽기 쉬운 차량·시간·상태를 표시합니다.

## 실패 대응과 검증

| 실패 | 복구·확인 |
|---|---|
| 해시 불일치·잘못된 요청 | 저장 성공으로 응답하지 않음 |
| 병합 중 서버 종료 | 미완료 작업 복구·revision 재실행 |
| 늦은 증거 | 다음 revision, 기존 완료 결과 보존 |
| 사고차 미수신 | 대체 타일. 파일 자체가 검정이라는 의미와 구분 |
| 인증 실패 | 영상 원본을 공개 경로로 우회하지 않고 권한 오류 |
| 비동기 UI 응답 경쟁 | 오래된 선택 응답·중복 클릭·모달 종료 후 응답을 시험 |

72개 Python·51개 Node 회귀 시험을 복제본에서 다시 실행합니다. 임시 fixture 검증이지 운영 부하·침투 시험·실차 증거 신뢰성 인증을 대신하지 않습니다.
