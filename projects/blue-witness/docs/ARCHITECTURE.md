## 카메라 메모리와 작업 분리

현재 팀 구현은 960개 NV12 버퍼를 미리 확보합니다. 최근 약 20초·최대 640프레임을 Ring에 유지하고 나머지 320개를 여유 버퍼로 둡니다. Snapshot의 참조가 살아 있는 프레임을 덮어쓰지 않으며, 추론·인코딩 완료 후 반환합니다. NV12 저장 공간만 약 421.875MiB이고 모델·카메라·인코더 메모리는 별도이므로 저메모리 장치에서 그대로 쓸 수 있는 구조는 아닙니다.

수신 스레드 → 이벤트 대기열 → Snapshot/AI Worker → 인코딩·파일 공개 → 인계 스레드로 긴 작업을 분리합니다. 인계 실패 시 MP4와 `.handoff`를 보관하고 재시도하며, 로컬 ACK와 서버 저장 ACK는 서로 다른 완료 단계입니다.

## 시간축

```text
공통 NTP → 각 Pi Chrony → FrameWallClock / 사고 시각
                               │
        Time Sync IPC → 상태·오차 메타데이터
                               │
capture_start_timestamp_ns + MP4 PTS → 각 프레임 절대 시각
                               │
                     서버 trim·padding·병합
```

시스템 시각 보정은 Chrony가 맡으며 Time Sync 서비스가 NTP를 새로 구현한 것은 아닙니다. IPC 응답의 상태·오차는 관찰값이고 모든 프레임에 정확한 동기를 보증하지 않습니다.

## 저장·병합·접근 제어

원본과 수신 DB를 보존하고 병합 결과는 revision으로 관리합니다. 수집 마감·병합 작업 선점·실패 재시도·늦은 영상 도착을 별도 상태로 다룹니다. 사고차 영상이 없으면 검정 대체 칸을 사용하며, 설정상 병합 제외 차량은 저장만 할 수 있습니다. 수신 원본 수와 실제 병합 수는 의미가 다릅니다.

HTTPS는 전송 암호화·서버 인증, 노드 API Key는 차량 노드 인증, SHA-256은 파일 무결성·재전송 확인을 맡습니다. 사용자는 차량 소유 관계와 영상 접근 세션을 확인하고 관리자는 역할 권한을 적용합니다. 화면의 시연용 본인·차량 확인은 실제 외부 신원 인증을 구현한 것으로 표현하지 않습니다.

## 배포 경계

CD는 Pi용 실행 파일·모델·설정을 대상으로 하며 FastAPI 서버의 운영 자동 배포까지 구현한 것으로 표현하지 않습니다. `workflow_dispatch`로 성공한 main CI의 SHA·산출물을 검증하고 self-hosted runner가 SSH로 적용합니다. 최초 장치 서비스·root helper·허용 명령 설정은 별도 운영 준비가 필요합니다.
